## 2026-08-03 — 第75章: 投資思想の再定義 ＋ 期の絞り込み ＋ UI/UX 総合改修

**指示**: ①メガスケーラー／中位株／マイクロキャップの評価思想を定義し直す。②複数期の資料が来たら 1 つに絞らせる。③期のパースとフォールバックを確定させる。④UI/UX 7 件（既定ウィンドウ・Ctrl+A・対話のリッチテーブル・引用の赤字・四半期比較・PDF 出力・Google 無料明記）。

**対応（① 投資思想）**:
- **メガスケーラー**: 判定の目的を「QQQ / S&P500 を買うより、サテライトとして
  組み込んでポートフォリオ全体をかさ上げできるか」に固定。
  **二段階評価を厳守させた** — 20 項目は結論に偏らず客観採点し、
  指数との比較は最後のまとめでのみ行う。
  途中で「サテライト向きだから加点」をやると採点が歪む。
  PBR/PER の単独不合格判定を禁止（**自社株買いで純資産が縮むのは高 ROE の裏返し**で、
  割高さの証拠ではない）。FCF マージン / Rule of 40 / EV・Gross Profit / モート持続性で見る
- **中位株（新規 `midcap`）**: トレンドに道具を売る「ツルハシ企業」として評価。
  **誰が勝っても売れる構図か**（顧客集中度）、受注残の質（キャンセル条項・集中）、
  リカーリング比率、取れる比率の伸びしろ。
  ピーク利益に対する低 PER を割安と書かせない（**ピークで安く見えるのは循環の常**）
- **マイクロキャップ（`role_growth.md` → `role_microcap.md`）**: ロマン枠として、
  Cash Runway・希薄化構造・単一プロダクト依存と特許モート・黒字化の道筋を厳格査定。
  **下方修正条項つきワラント**（株価が下がるほど希薄化が進む構造）を必ず指摘させる。
  赤字期の PER/PBR 判定はやめ、**成長率 vs バーンレート**を軸にする
- **id は保存データの鍵なので変えない**（`growth` のまま中身を差し替えた）

**対応（② 複数期の絞り込み）**:
- `collectFiscalPeriods` で資料を期ごとにまとめ、2 種類以上なら選択させる
- **混ぜて分析させない。** どの数字がどの期のものか分からない結果ができる
- 選ばなかった期の資料は使わない旨も画面に出す

**対応（③ 期のフォールバック）**:
- 初期選択は「資料から読めた期 → ファイル名 → SEC に出ていそうな最新期」の順
- **見積もりは 1 四半期前。** 四半期報告は期末から 40〜45 日遅れるので、
  8 月なら Q2（4〜6 月期）が直近の提出分。年初は前年 Q4 へ戻す
- 見積もり由来であることを画面に出す（確度が違うため）
- **添付資料があるなら、SEC が取れなくても中断しない。**
  PDF と財務データだけで分析は成立する。
  期の指定は「その期の資料を入れた」という意思表示なので、
  SEC 側の未提出を理由に止めると手元の資料を使えないまま終わる

**対応（④ UI/UX）**:
- 既定ウィンドウを 1440x900 → **1680x1000**（分析ボタンが最初から画面内に収まる）
- **Ctrl+A を分析本文だけに限定。** 既定のままだとサイドバーやボタンのラベルまで
  選択され、コピーしても使えない。**入力欄の中では既定の挙動に任せる**
- 対話の本文で Markdown テーブルを表として描画し、**RAW 切り替え**を付けた
  （コピーして他所へ貼るときは素のテキストが要る）
- 引用行に目印（`> `）を付けて赤字表示。自分が書いた文と貼り込んだ引用を見分けられる
- ポートフォリオ履歴に**四半期比較**を追加。期を 1 つ選ぶと、
  銘柄横断でブロック別スコアまで並ぶ。同じ期に複数あれば最新を採る
- エクスポートに **PDF** を追加。**PDF ライブラリは足さない**
  （日本語の埋め込みフォントで数 MB 増え、「超軽量」の方針に反する）。
  印刷ダイアログの「PDF として保存」に載せ、OS のフォントで描かせる。
  行がページをまたがないよう `page-break-inside: avoid` を効かせた
- Google 認証ガイドに「クライアント ID の発行・利用は完全無料です」を明記
  （費用がかかると誤解されると、ここで止まってしまう）
- ディベートの 🔥 スイッチは削除されておらず、分析ヘッダーに残っていることを確認した

## 2026-08-03 — 第74章: コンテキスト分離 ＋ 進捗の固定 ＋ スコア演出 ＋ 詳細ログ

**指示**: ①各ステップに直前ステップの出力を含めず、「一次資料 ＋ YF 財務データ」だけを独立して送る（雪だるま式のトークン膨張を止める）。②進捗メーターと消費トークンをスクロールしても消えないよう固定。③平均スコアを分析中は隠し、完了時にカウントアップで確定表示。④決算期ダイアログでファイル名からの期パースと「本決算／アドホック」選択を追加。⑤エラー詳細をモーダルで表示・コピーできるようにする。

**対応（① コンテキスト分離）**:
- **採点段（1〜3）に直前の出力を渡すのをやめた。** 前回の分割実装では
  各段に前段の本文を渡していたため、段を追うごとにプロンプトが積み上がり、
  資料と合わせて 10 万トークンを超えて切断されていた。
  分割したのに切れる、という状態の原因はここ
- 各段は「一次資料 ＋ 財務データ」だけを見て担当範囲を独立に採点する。
  通しの体裁（表のヘッダー、節の順序）は最後にフロント側で組み立てる
- **最終段だけは評価テーブルの「行」を渡す（`scoreRowsOnly`）。**
  矛盾の指摘と死角チェックは、何が書かれたかを読まないと成立しない。
  ただし前置きや強み・リスクの節は落とし、行だけにする
- 指示文にも「担当範囲の行だけを書く。他の行は別途評価している」を足した

**対応（② 進捗の固定）**:
- スクロール領域の**外**へ出した。sticky を効かせるより確実で、そもそも流れない
- 消費トークンと概算コストを同じ枠へ入れ、**走行中も見える**ようにした
  （終わってから合計だけ見せても、途中で止めるかの判断に使えない）

**対応（③ スコアのカウントアップ）**:
- **生成中は出さない。** 段ごとに採点しているので、途中の平均は
  「まだ採点していない項目を除いた平均」でしかなく、確定値と取り違える
- 全段完了後に 0 から回して確定させる。終盤で減速させて確定感を出す
- 計算は `countUp.ts` に切り出した（描画から離せばテストできる）
- 同じスコアで何度も回さない（再描画のたびに演出が走ると鬱陶しい）

**対応（④ 決算期ダイアログ）**:
- 本文から読めなければ**ファイル名**を見る（`FY26_Q3.pdf` 等）。
  拡張子を落とし、`_ - .` を空白へ均してから本文と同じ規則に乗せる
- 判定元がファイル名だったことを画面に出す（本文より確度が落ちるため）
- 「本決算（実績）／追加資料・見通し（アドホック）」の選択を**常に出す**。
  既存の有無で出し分けていたが、**見通し資料を本決算として記録すると、
  あとから実績と見分けが付かなくなる**

**対応（⑤ エラー詳細モーダル）**:
- 生ログを、銘柄・プロバイダ・モデル・完了段と一緒にモーダルで表示
- **そのままコピーできる形にする。** 問い合わせを受ける側が最初に聞くのは
  「実際のメッセージ」と「どのモデルで起きたか」で、画面の文言では切り分けられない
- 折りたたみをやめてモーダルにしたのは、その場に広げると本文が押し出されるため

## 2026-08-03 — 第73章: 分割直列実行 ＋ チェックポイント ＋ 使用量・診断・進捗

**指示**: ①20 項目を「1〜7 / 8〜14 / 15〜20 / 全体俯瞰」の 4 段に分けて直列実行し、段ごとに `analyses.db` へチェックポイント保存して再開できるようにする。②途中で切れても生成済みを保持し、完了時には必ず履歴・ポートフォリオへ保存する。③資料なしのときは「最新期／過去の期」を選ばせ、指定期の SEC 書類を取得する。④`usage` から消費トークンを記録し、概算コストを表示する。⑤エラー原因を切り分けて対処法を示し、5 段階の進捗メーターを出す。

**対応（① 分割実行とチェックポイント）**:
- **一度に 20 項目を書かせない。** 出力上限で切れると、
  そこまでの生成がまるごと無駄になり、保存も走らないので
  「分析したのに何も残らない」状態になっていた。これが今回の主因
- `analysisSteps.ts` に段の定義と結合を切り出した。
  7 / 7 / 6 に割ったのは 1 段あたりの出力長を揃えるため。最終段は採点せず死角チェック
- 段が終わるたび `analysis_steps` テーブルへ保存し、次回はその続きから
- **歯抜けは土台にしない（`usableSteps`）。** 1 と 3 だけ残っていても、
  3 は 2 を読まずに書かれているので通しで読むと辻褄が合わない。
  先頭から連続している分だけを使う
- **中断された段は確定させない。** 途中までの行を保存すると、
  次回に欠けた表を土台にしてしまう
- 各段には表の本文行だけを書かせるので、**結合時にヘッダーを補う**。
  素で連結するとヘッダーの無い表になり、パーサが 1 行も拾えない。
  モデルがヘッダーを付けてきた場合は落とす（表の途中に挟まると行を取り違える）

**対応（② 保存の確実化）**:
- 分割したこと自体が対策になっている。切れても直前の段までは DB にある
- 全段完了時だけ途中経過を捨てる。完了していなければ次回に持ち越す

**対応（③ 資料なし時の期の選択）**:
- 決算期ダイアログに `noDocument` モードを足した。既定は「最新期」
  （過去を掘るのは意図がある人だけ）
- `edgar::PeriodFilter` を新設し、`report_date` の年・四半期で絞る
- **見つからなければ分析を止める。** 黙って別の期の書類で続けると、
  頼んだ期の分析として違う期の中身が保存される
- 壊れた日付は「合致しない」扱い（通すと同じ事故になる）

**対応（④ 使用量とコスト）**:
- SSE の全ペイロードから usage を拾う。**3 社で名前が違うだけなので 1 か所で見る**
  （プロバイダごとに書き分けると、追加のたびに拾い漏れが出る）
- 複数回流れてくるので大きいほうを採る（上書きすると先に来た入力トークンが消える）
- **OpenAI は `stream_options.include_usage` が無いとストリーミングで usage を返さない**
- **取れなかったら 0 のまま。** 推定で埋めると、請求額とかけ離れた数字を
  「実測」として見せることになる
- 単価不明のモデルは金額を出さない（桁違いを避ける）
- 表示は「消費: 12,400 tkn / 約 ¥5.2（$0.034）」。**概算である旨をツールチップに残す**
- `analysis_history` にも `input_tokens` / `output_tokens` を追加

**対応（⑤ 診断と進捗）**:
- `diagnose.ts` で 429 / 401 / 403 / 404 / 残高不足 / 出力切れ / 通信断 を切り分ける
- **再試行して直るものだけ再試行を勧める。** 401 を何度叩いても直らない
- 認証・モデル誤りは設定へ導く。**残高不足はどちらも出さない**（アプリ側では直らない）
- 元のメッセージは折りたたんで残す（問い合わせに要るが、最初から見せると読む気が失せる）
- 5 段階の進捗メーター。終わった段は緑で確定させ、**そこまでは保存済み**であることを示す

## 2026-08-03 — 第72章: 決算期の承認 ＋ SEC 自動取得 ＋ アドホック分析の入れ子ツリー

**対応（① 決算期の承認）**:

- **判別できなかったときも同じダイアログを出す。**
  「分かりませんでした、選んでください」と聞けば期を記録できる。
  黙って期なしで進めると、あとからヒートマップの期と突き合わせられない

  永続化すると、資料を入れ替えても古い確定が効いてしまう

## 2026-08-01 — 修正: コントロール類のサイズ固定 ＆ パネル D&D の進入禁止マーク解消

**指示**: 実機操作で発生した 2 件の不具合（Web 標準仕様の考慮漏れ）を至急修正。①フォントサイズを変えるとスライダーやコマンドバーのパーツまで拡大縮小し、カーソルから逃げて操作不能になる。スライダーや A− / A+ には絶対値を直接指定し `--fs-base` の影響を一切受けない完全固定にすること。②グリップをドラッグしても進入禁止マーク（🚫）が出てドロップできない。ドロップ先のヘッダーに `onDragOver`（必要なら `onDragEnter`）の `preventDefault()` を実装すること。

**対応（① サイズ固定）**:
- **真因は `:root { font-size: var(--fs-base) }`。** `:root` の font-size は `rem` の基準であり、
  Tailwind の余白・幅・高さはすべて `rem` で表現されている。
  そのため文字を大きくするとボタンやスライダーまで太り、
  **カーソルの下から要素が逃げて操作不能**になっていた
- 指定を `:root` → `body` へ移動。`rem` の基準は 16px のまま固定され、
  文字だけが継承でアプリ全域に連動する（Step 5.4 の要件④は維持）
- `.ui-fixed`（12px 固定）を新設し、右上のコントロール群
  （AI設定ボタン ＋ フォント調整 UI）をまとめて適用。
  **上の AI設定ボタンが太るとスライダーが下へずれる**ため、群ごと固定する必要がある
- `FontSizeControl` の各部品を絶対値 px で固定
  （ボタン `h-[22px] w-[26px]` / スライダー `h-[4px] w-[72px]` / 表示幅 `w-[34px]`）
- `ProviderMenu` の `t-label` / `t-body` を外し、`.ui-fixed` の 12px を継承させた

**対応（② D&D）**:
- HTML5 Drag and Drop は、ドロップ先が **`dragenter` と `dragover` の両方で
  `preventDefault()` を呼ばない限りブラウザ既定の拒否が働き 🚫 が出る**。
  従来は `dragover` のみ、しかも MIME 種別の判定を通ったときだけ打ち消していた
- 判定を挟まず必ず打ち消す `allowDrop` に統一し、`onDragEnter` にも割り当てた
- `dragstart` で `text/plain` にも同じ値を入れ、カスタム MIME を落とす環境でも成立させた
- `dragleave` は `relatedTarget` が子要素なら無視し、枠のちらつきを解消
- なお `tauri.conf.json` の `dragDropEnabled: false` は設定済みで、
  WebView 側で HTML5 D&D が有効になっていることを確認した

`src/components/PanelHeader.tsx`, `PROGRESS.md`, `改修記録.md`

## 2026-08-01 — 修正: GPT-5 系で送信が 400 になる問題

**指示**: OpenAI のキーを入れたが、対話パネルで
`OpenAI互換 API エラー (HTTP 400): Unsupported parameter: 'max_tokens' is not supported with this model. Use 'max_completion_tokens' instead.`
が表示される。

**原因**: OpenAI互換を名乗る API 間でパラメータの方言が揃っていない。

| 実装 | 出力上限 | temperature |
| --- | --- | --- |
| GPT-5 系（api.openai.com） | `max_completion_tokens` のみ | 既定値のみ（0 を送ると 400） |
| GPT-4o 系 | `max_tokens` | 任意 |
| DeepSeek 等の他社互換 API | `max_tokens` のみ | 任意 |

固定で `max_tokens` + `temperature: 0.0` を送っていたため GPT-5 系で弾かれていた。

**対応**:
- `llm/openai.rs` にパラメータの方言吸収を実装。まず本命の形で送り、
  400 が返ったらエラーメッセージを読んでパラメータを調整し自動で再送する（最大 3 回）
  - 本家 OpenAI (`api.openai.com`) は `max_completion_tokens` を本命に、他社互換は `max_tokens` を本命にする
  - 出力上限パラメータの切り替えは 1 回だけ（往復による無限ループを防ぐ）
  - `temperature` を拒否された場合は temperature を外して再送
- 対話パネルに、選択中プロバイダの設定不足を常時知らせる警告バーを追加
  （従来は会話が始まると案内が消え、原因に気づきにくかった）
- OpenAI のモデル名ヒントを `例: gpt-5.6 / gpt-4o` に更新

**画面に出ていた他の 2 件について**: 「OpenAI互換」「Anthropic (Claude)」の
「APIキーが未設定です」は不具合ではなく、その時点で選択中だったプロバイダに
キーが無かったための正常な警告。上記の警告バー追加で気づきやすくした。

**変更ファイル**:
- 変更: `src-tauri/src/llm/openai.rs`, `src-tauri/src/llm/mod.rs`
- 変更: `src/components/ChatPanel.tsx`, `src/lib/config/providers.ts`
